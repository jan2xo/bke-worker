# Desktop WebExtension native-host P-256 proof client — SOURCE ONLY

Parent mission: Command Center [issue #30](https://github.com/jan2xo/bke-command-center/issues/30); follows BKE Worker [PR #105](https://github.com/jan2xo/bke-worker/pull/105) (nonexportable profile key), [PR #106](https://github.com/jan2xo/bke-worker/pull/106) (standalone native-messaging Node host), Command Center [PR #56](https://github.com/jan2xo/bke-command-center/pull/56) (inert private device admission seam).

## Purpose and execution

The new module `src/native-proof-client.ts` implements the exact source-level Chrome native messaging client for the existing executable at `browser-extension/native-host/entry.mjs`. This is **not** a deployed, registered or user-enabled native messaging connector. The checked-in `manifest.json` has only `storage`; no `nativeMessaging` permission is granted. `service-worker.ts`, popup and content scripts do **not** import or invoke this new module. `connectNative` is behind an explicit, separately injected, invocation requiring a future owner-approved registration and runtime permission intent; no network, prompt dispatch, automatic restart or background polling was added.

At the trusted extension-owned call site, the client obtains the exact extension origin from `runtime.getURL("")` and sends one `HELLO` with `worker-a`-style configured worker ID, the existing IndexedDB public P-256 JWK, three **preverified owner-pinned resource fingerprints** (dedicated ChatGPT target, browser profile, bridge identity) and a fresh cryptographically generated 256-bit client nonce. Host name is fixed to `bke.worker.desktop` (a registration contract for the separate Go-account installer lane). The client never accepts a host name, extension origin, Chrome permission, remote URL, GitHub token, browser cookie or private P-256 key through a device message.

The injected Chrome port's next message must be the **exact** PR #106 `CHALLENGE` shape: `type=CHALLENGE`, `version=1`, a matching client nonce, a distinct 256-bit server nonce, identical profile binding hash and expiry no later than 15 seconds into the future. The dedicated internal `createDeviceIdentityBridge(...).signNativeProof` checks an exact, domain-separated `bke-worker/desktop/native-key-proof/v1` JSON array over extension origin, worker, public key fingerprint, profile binding, all three resource hashes, both nonces and expiry; the existing profile-locked **nonextractable IndexedDB CryptoKey** signs once after a serialized durable nonce claim. No arbitrary message-signing API, popup/runtime signing message, private key export or token storage exists.

The client then transmits a single `PROOF` (two matched nonces, P-256 IEEE-P1363 signature), accepts only a strictly shaped `LOCAL_PROOF_OK` carrying exactly the same worker and public-key hash and the explicit values `admission_authority=NONE` and `dispatch_authority=NONE`. It closes the port on both success and uncertainty. Any malformed, stale, replayed, duplicate or cross-profile challenge and any privileged/wrong receipt fail closed. **No auto-retry** after an uncertain proof delivery, browser-service-worker suspension, host crash or channel disconnection; doing so could double-sign/use one proof. The in-process 10-second test budget is separate from the host challenge's maximum 15-second protocol expiry: both apply independently.

## Authorization remains locked

A local P-256 signature demonstrates possession of a browser extension profile's key. It is *not* Chrome OS native-host installation attestation, an authenticated Command Center server session, a worker GitHub PR assignment, a pairing consent, an active worker lease or a ChatGPT authentication credential. The host's Chrome argv origin is only a claim until its installation path, manifest `allowed_origins`, OS owner ACL and installer provenance are verified by the separate Go-account installer work. Command Center still needs independently trusted server-side native peer attestation and real human Admin Access with reviewed resources. Browser-profile cloning can duplicate a non-hardware-bound IndexedDB key, so the profile must be isolated and managed. Android GeckoView uses a different native messaging adapter and must not be inferred live from these tests.

## Deliberate parallel ownership split

**Lane A (this PR)** is limited to `browser-extension/src/device-identity.ts`, `src/native-proof-client.ts`, extension tests and documentation. **Lane B (other Go account)** owns the host installer Bash entrypoint, manifest/launcher verification, rollback and related isolated tests. Neither lane edits the other's PR, installs a native host, authorizes a browser permission or assumes an active `bke-worker:* ` label.

## Certification

The existing conditional exact-head WebExtension CI executes Node 22 TypeScript build, unchanged browser manifest audit and Node/WebCrypto tests. Adversarial tests cover fixed-domain proof interoperability with PR #106's canonical encoder, one-use durable nonce races and invalid proof inputs, forged elevated receipts, profile/worker mismatches, channel disconnect, and a **real Node child-process Chrome binary framing** handshake against the previously merged native host implementation. No real Chrome installation/permission, OS trust, real human-authenticated ChatGPT continuation, Cloudflare PREPRODUCTION or production deployment is claimed. Parked Worker PR #90 untouched.
