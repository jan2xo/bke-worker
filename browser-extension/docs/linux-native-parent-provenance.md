# Linux native host parent-process provenance — SOURCE ONLY

Parent: Command Center issue #30. Depends on merged Worker PRs #108 (operator-only Chrome host installer), #109 (separate dormant P-256 signer), #110 (read-only installer byte integrity), and Command Center PR #57 (dormant attestation verifier).

`browser-extension/native-host/linux-parent-provenance.mjs` is a **Linux-only, read-only kernel process witness** for a future private OS session adapter. It inspects the **current Node host PID and its immediate real parent** in actual Linux `/proc`. No PID, procfs root, kernel evidence callback, binary path, or expected digest is accepted from Chrome/device JSON. The trusted local caller must supply a separately human-reviewed exact browser executable path + SHA256, current Node host executable path and expected local UID. The module checks real procfs magic, both stat process identities and birth start ticks, UID/effective UID, current host executable, parent executable symlink, size/permissions, SHA256 of the parent's *running executable*, then rechecks kernel ancestry and executable identity after hashing. Missing evidence, parent exit/reuse, exec replacement, mismatched digest/path/UID, symlinked ancestor, non-Linux, or budget exceed fail closed.

A successful result is `NATIVE_PARENT_EXECUTABLE_MATCHED` with `browser_session_authority=NONE`, `profile_authority=NONE`, `device_admission_authority=NONE`, `dispatch_authority=NONE`. This can witness an immediate parent binary identity on Linux, **not prove** that Chrome owns a specific extension, tab, human-authenticated ChatGPT profile, or native messaging session. A process of the same OS user can itself launch that browser executable; digest alone is not an authorized actor. The real Chromium process graph may have intermediate launchers: this first version intentionally requires an immediate parent and **fails closed** rather than guessing ancestry. Cross-platform macOS and Android GeckoView adapters must be separate certification work.

No module is imported by the current Chrome native host entrypoint, extension, installer, Cloudflare runtime or PR dispatch. No Chrome installation/permission changes, tokens, device-key enrollment, production or PREPRODUCTION activation.

Required certification: exact-head WebExtension/native Node 22 tests incl **actual Linux /proc subprocess positive** on GitHub Linux runner and negative owner pins/identity checks, existing PR Guard, source/security review. No live Chrome assertion.
