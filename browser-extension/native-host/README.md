# BKE Worker desktop Chrome native-messaging host — SOURCE ONLY

Parent mission: [Command Center issue #30](https://github.com/jan2xo/bke-command-center/issues/30). Follows Worker PR #105 (extension-local nonexportable P-256 device key) and Command Center PR #56 (default-OFF private admission gateway). Host implementation is in `browser-extension/native-host/` and is **not registered with Chrome, launched by the checked-in WebExtension or connected to Cloudflare**.

## Executable wire

`node browser-extension/native-host/entry.mjs <absolute-owner-policy-json-path> <chrome-extension://32-character-chrome-id/>` is an executable Node 22 program that reads Chrome native-messaging frames from stdin and emits only binary little-endian uint32 length-prefixed JSON frames to stdout. This command illustrates an isolated source/CI interface; it is **not** an operator activation instruction. Future installation must use the mandatory repo-tracked `bash <script>` owner-only entrypoint and OS Chrome registration/manifest.

The host accepts **exactly two** bounded messages on one process: a `HELLO` with exact fields `type,version,worker_id,public_key,resources,client_nonce`, and a `PROOF` with exact `type,version,client_nonce,server_nonce,device_signature`. It checks a strictly parsed owner-pinned policy: exact allowed extension-origin string, worker ID, canonical SHA-256 of the public JWK, three resource hashes, separate browser profile SHA-256 pin, and owner expiry. It then issues a fresh random 256-bit host nonce in a `CHALLENGE` with a 15-second maximum expiry. The client proves possession of the pinned device private key using 64-byte P-256 IEEE-P1363 ECDSA over a canonical domain-separated JSON array (audience `bke-worker/desktop/native-key-proof/v1`) binding origin, worker, public key digest, all three resources, profile binding, both nonces and expiry.

On a genuine signature, the host returns only a bounded `LOCAL_PROOF_OK` with `admission_authority=NONE` and `dispatch_authority=NONE`. It does NOT issue any bearer token, OAuth assertion, GitHub permission, Cloudflare Access identity, pairing consent, active worker assignment or Command Center trust credential. No device content, browser cookies, credentials or private key are recorded. Malformed/partial/oversized frames, wrong identity, replayed proof, invalid signature, expired challenge or unsafe policy abort the process without successful response.

**Important security separation:** `claimedOrigin` is an untrusted argv value on its own. Only a human-approved native-host manifest with Chrome's `allowed_origins`, the OS registration path and verified installer ownership can establish browser-origin trust. A local process can invoke this executable with forged argv; its signature check still proves possession of the pinned key, but the host alone is **not a Command Center-trusted transport attestor**. Server acceptance needs a separately certified host identity/attestation rooted in provider/OS trust and pinned on the Command Center. An unpaired device's self-asserted labels, public key and P-256 signature never authorize pairing on their own.

## Policy and platform locks

Only absolute path policy files are allowed. On the Linux CI host, `O_NOFOLLOW`, owner UID equality, no group/world writable bits, regular-file check and a 4 KiB upper bound are required. The same Unix ownership primitive is supported for prospective macOS testing but **macOS has not been live tested**. Windows ACL equivalence is **not certified**, so the executable refuses operation when Unix ownership/no-symlink evidence is unavailable; a separate Windows-native install and policy validation must be certified. The policy is non-secret but an integrity control. This PR never writes, provisions or installs a policy file outside isolated CI test fixtures.

The extension's `manifest.json` continues to exclude `nativeMessaging`, so the current checked-in extension cannot call this host. There is no `chrome.runtime.connectNative` call, native-host manifest installation, persisted session, reconnect manager, WSS, GitHub PR claim or device enrollment. The distinct subsequent dependencies are (a) source-only extension-side native signer/client adapter with independent browser-origin verification, (b) owner-only browser native-host manifest registration and profile/host pinning through a single repo-tracked script, and (c) a separately trusted, server-verified host identity and Command Center admission, followed by live human acceptance and separately certified dispatch.

## Certification

The existing path-conditional exact-head PR Guard WebExtension job runs Node 22 TypeScript/manifest checks (the original 17 device identity tests) plus `npm run test:native` (real subprocess and malicious wire tests). Tests cover frame fragmentation, malformed/truncated/oversized input, genuine P-256 signature, hostile alternative key/worker/resources, tampered proof and nonces, cross-session replay, timeout, policy expiry/mode and symlink rejection, and binary-only child-process output.

This certifies a real **host executable and its local verification protocol**, not Chrome installation, GeckoView compatibility, transport enrollment or actual authenticated ChatGPT. No secrets, browser profile data, production change, Cloudflare PREPRODUCTION activation, nativeMessaging permissions or parked PR #90 wake.
